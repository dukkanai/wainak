# تشغيل wainek ونقله بين الخوادم

نعتمد Docker Compose على خادم واحد للبداية، مع PostgreSQL مستقل عن خدمات البريد والمواقع الأخرى. هدف النقل إلى خادم أكبر أقل من ثلاث ساعات، بشرط تجهيز الوصول للخادم الجديد مسبقًا وقياس حجم البيانات وسرعة نقلها واستعادتها. هذا هدف تشغيلي يحتاج تجربة كاملة، وليس ضمانًا توفره الحاويات.

## ما يشمله التجهيز

ملف `compose.yaml` يشغل PostgreSQL 17 بصورة مثبتة بالبصمة، وقرص دائم مستقل، وشبكة داخلية دون نشر منفذ على المضيف. حد الذاكرة 512 ميجابايت والمعالج واحد، لحماية الخدمات الموجودة على الخادم. هذه حدود بداية التطوير وليست تقديرًا لسعة مستخدمين معينة. Docker موجود على المضيف ولا يحتاج إعادة تثبيت.

كلمة المرور مولدة محليًا داخل `.runtime/db_password` بصلاحيات مقيدة، ومركبة داخل الحاوية كملف سر. لا توجد كلمات مرور في ملف Compose. هذه الآلية ليست تشفيرًا للسر على قرص المضيف؛ مدير الخادم ومن يملك صلاحية Docker يستطيعان الوصول إليه.

المستخدم `wainak_admin` إداري فقط. قبل تشغيل خدمة التطبيق ننشئ لها مستخدمًا محدود الصلاحيات، ومهاجرات مخطط قاعدة البيانات، وفحوص الصلاحيات والمعاملات. لا يستخدم التطبيق حساب الإدارة.

قاعدة البيانات لحسابات المستخدمين والمطابقة وحالة العلاقات والمشتريات والبيانات الإدارية اللازمة فقط. لا تنشئ هذه البنية تخزينًا للمحادثات أو الصور أو الصوت أو نتائج الألعاب. نراجع أي تسجيل أخطاء أو مراقبة مستقبلية كي لا تجمع هذه المحتويات.

التطبيق وواجهته البرمجية والمصادقة ونظام الدفع وخدمة تمرير الاتصال لم تُبن بعد. لا توجد واجهة عامة أو نطاق مرتبط بهذا التجهيز.

## تشغيل الأساس وفحصه

من مجلد المشروع:

```bash
python3 ops/manage.py up
```

```bash
python3 ops/manage.py status
```

التهيئة وإنشاء الأسرار تتمان تحت قفل محلي عند أول تشغيل فقط. إذا وجد نشر سابق وفقد السر، ترفض الأداة توليد بديل مضلل؛ يلزم استعادة السر الأصلي أو إجراء تدوير صريح. أمر `status` لا ينشئ ملفًا أو يغير صلاحية، ويفحص المصادقة الفعلية عبر TCP بالسر دون طباعته. القفل المحلي لا يمثل قفلًا على كل مدير أو اتصال بالقاعدة. لا تستعمل `docker compose down --volumes` على مشروع وينك؛ فهو يحذف قرص البيانات.

## النسخ والاستعادة

```bash
python3 ops/manage.py backup
```

ينشئ الأمر ملف PostgreSQL بصيغة custom داخل `backups`، ومعه ملف JSON يتضمن الحجم والبصمة والتاريخ وإصدار قاعدة البيانات. ملفات النسخ محلية بصلاحيات مقيدة، لكنها غير مشفرة، ولا تنجو من فقدان الخادم. لا توجد حاليًا جدولة آلية أو سياسة حذف للنسخ؛ راقب المساحة حتى تجهيز وجهة النسخ الخارجية والاحتفاظ.

نسخة قاعدة البيانات لا تشمل أدوار PostgreSQL العامة ولا إعدادات النطاق ولا الصور التنفيذية ولا مفاتيح توقيع الجلسات أو مفاتيح الخدمات الخارجية. تحفظ تعريفات الأدوار والمنح المستقبلية في مهاجرات قابلة للتكرار، وتحفظ الأسرار في مسار استعادة مستقل وآمن. خيارات `--no-owner --no-acl` تعني أن منح الصلاحيات يجب إعادة تطبيقها قبل تشغيل التطبيق بعد النقل.

لتجربة استعادة محلية معزولة:

```bash
python3 ops/manage.py restore-drill
```

ينشئ الأمر نسخة حالية ويستعيدها داخل حاوية مؤقتة دون شبكة أو منافذ وبسر مؤقت مستقل عن سر التشغيل، ثم يحذف الحاوية وبيانات تجربتها فقط. مساحة التجربة المؤقتة 256 ميجابايت، لذا تخص قاعدة البداية الصغيرة. عند نمو البيانات، تصبح التجربة على خادم اختبار بقرص مناسب بدل هذا الاختبار المحدود.

عند تمرير أرشيف موجود بدل إنشاء نسخة محلية جديدة، يتطلب الأمر `--trusted-source` لإقرار المشغل بأنه تحقق من مصدره. العلم ليس توقيعًا ولا يثبت المصدر تقنيًا. يمكن إضافة `--expected-sha256` ببصمة وصلت من قناة موثوقة مستقلة. تتحقق الأداة من نسخة مؤقتة خاصة من البايتات وتستعيد المقبض نفسه؛ لا تعيد فتح مسار المصدر بعد التحقق. مساحة هذه النسخة المؤقتة تضاف إلى احتياج القرص أثناء الاستعادة.

اختبار بيانات اصطناعية يتحقق من حفظ النص العربي والمبالغ، ويرفض النسخة التالفة والكتابة فوق قاعدة تحتوي بيانات:

```bash
python3 ops/test_recovery.py
```

لا يعتبر ملف JSON توقيعًا أمنيًا ضد العبث المتعمد؛ هو فحص لسلامة النقل. لا تستعد إلا نسخة من مصدر موثوق. يجب تشفير النسخ قبل رفعها خارج الخادم، والاحتفاظ بمفتاح فكها خارج الخادم أيضًا. تحديد الوجهة وتفعيل الجدولة والتنبيهات شرط قبل استقبال بيانات حقيقية.

## خطة النقل خلال ثلاث ساعات

الميزانية التالية هدف أولي قدره 170 دقيقة، مع احتياط 10 دقائق. تحسب من بدء تجهيز الخادم المتاح بالفعل إلى قبول التطبيق على الوجهة الجديدة. شراء الخادم أو انتظار توفره وتغييرات مزودي الخدمات قد تزيد المدة.

1. خلال 30 دقيقة: تجهيز الخادم الجديد، وتثبيت Docker وCompose، وضبط الوصول والجدار الناري والوقت والمساحة.
2. خلال 20 دقيقة: نسخ إصدار المشروع نفسه وصور التطبيق المثبتة وإعداداته، وتجهيز الأسرار بأمان. يمكن تنزيل الصور قبل موعد النقل. يجب أن تدعم الصور معمارية الجهاز الجديد.
3. خلال 50 دقيقة: إدخال التطبيق في الصيانة وإيقاف جميع مصادر الكتابة، بما فيها العاملون في الخلفية ومعالجات أحداث الدفع، ثم أخذ النسخة النهائية ونقلها عبر SSH مع ملف البصمة واستعادتها. يجب أن يعيد مزود الدفع محاولة الأحداث أو نوفر طابورًا دائمًا قبل اعتماد هذا المسار.
4. خلال 25 دقيقة: إعادة تطبيق الأدوار والصلاحيات اللازمة، ثم فحص تسجيل الدخول والملفات والمشتريات وحصرية العلاقة والحظر عبر النطاق على الوجهة الجديدة. البيانات والجلسات ومفاتيحها يجب أن تبقى متسقة.
5. خلال 15 دقيقة: تحويل النطاق أو الوكيل العكسي وTLS. نخفض TTL مسبقًا، ونعالج العملاء الذين يصلون إلى العنوان القديم بتوجيههم للوجهة الجديدة أو إبقائهم في الصيانة؛ لا نسمح بكتابات مستقلة على الخادمين.
6. خلال 30 دقيقة: المراقبة وقبول التشغيل وتوثيق وقت النقل، مع إبقاء المصدر متوقفًا عن الكتابة واحتفاظه بنسخة مؤقتة للتراجع.

قبل جدولة أي نقل، نقيس وقت النسخ والاستعادة والنقل على حجم مماثل للإنتاج. إذا تجاوز التقدير هذه الميزانية، نجهز مزامنة مسبقة أو نسخًا مستمرًا بدل الاعتماد على نقل كامل أثناء الصيانة. زمن توقف المستخدمين جزء من هذه النافذة وليس بالضرورة ثلاث ساعات.

أوامر قاعدة البيانات على خادم جديد فارغ بعد نسخ المشروع:

```bash
python3 ops/manage.py up
```

انقل ملف `.dump` وملف `.json` المجاور من المصدر إلى وجهة آمنة عبر SSH. استبدل المسار التالي بالنسخة الفعلية:

```bash
python3 ops/manage.py restore-empty /secure/path/wainak-backup.dump --database wainak_restore_20261024 --trusted-source
```

تغير عقد الأمر: ينشئ قاعدة جديدة باسم يبدأ بـ`wainak_restore_`، ويرفض أي اسم موجود حتى لو كانت قاعدته فارغة. لا يكتب فوق قاعدة `wainak` ولا يعطل اتصالات قاعدة موجودة. إنشاء PostgreSQL يحسم سباق اسم الوجهة، وتبقى الوجهة الجديدة بحد اتصالات عادية صفر أثناء القبول؛ يستطيع مشرف PostgreSQL الموثوق تجاوز هذا الحد، فلا يدعي عزلًا عن مدير القاعدة.

عند فشل الاستعادة تبقى القاعدة الجديدة المحجوزة للفحص، ولا تحذف تلقائيًا ولا تحول إليها خدمة التطبيق. عند النجاح تطبق الأدوار والمنح وتفحص البيانات ثم تعدل إعداد قاعدة التطبيق صراحة إلى الاسم الجديد، وبعد القبول يرفع حد الاتصالات تحت إشراف المشغل. مثال SQL ينفذ فقط بعد القبول على الوجهة الصحيحة:

```sql
ALTER DATABASE wainak_restore_20261024 CONNECTION LIMIT -1;
```

يبقى المصدر متوقفًا عن الكتابة حتى يكتمل التحويل حسب الخطة. لا يكفي نجاح `SELECT 1` لقبول النقل. بعد التحويل يجب تحديد اسم القاعدة الفعلية في أوامر الفحص والنسخ؛ القيمة الافتراضية للأداة ما زالت `wainak` ولا تتحول تلقائيًا:

```bash
python3 ops/manage.py status --database wainak_restore_20261024
```

```bash
python3 ops/manage.py backup --database wainak_restore_20261024
```

## التراجع

قبل قبول أي كتابة على الوجهة الجديدة، يمكن الرجوع إلى المصدر المحفوظ بعد التأكد من أنه لم يتغير. بعد بدء الكتابة على الوجهة الجديدة لا نعيد النطاق إلى نسخة المصدر القديمة؛ نوقف الكتابة وننقل البيانات الأحدث أو نصلح الوجهة، حتى لا نفقد مشتريات أو تغييرات علاقات حدثت بعد التحويل.

## المتبقي قبل إطلاق الجمهور

أضافت [المراجعة الأمنية الأولى](reviews/security.md) ملاحظات محددة على فقد ملف السر، وعزل سر تجربة الاستعادة، والتحقق من وجهة الاستعادة وملف النسخة. طبقت إصلاحات الأدوات في الدفعة الأولى، وتفاصيل نتائجها وحدودها في [تقرير الإصلاح الأمني](reviews/security-fixes.md). تبقى النسخ المشفرة خارج المضيف والجدولة والمراقبة غير منفذة؛ لا تغلق إصلاحات الأدوات هذه المتطلبات.

بناء التطبيق وخدمة خلفية بصورة Docker دون الاعتماد على مسارات المضيف، وحساب قاعدة بيانات محدود الصلاحيات، ومهاجرات قابلة للتكرار، وربط النطاق وTLS، وتشفير وجدولة النسخ خارج الخادم، والتنبيه عند فشلها، ومراقبة الصحة والمساحة والموارد، واختبار الضغط والاستعادة والنقل بين جهازين. نضبط استراتيجية نشر تحديثات التطبيق والتراجع عنها مع مراعاة توافق مخطط قاعدة البيانات.

الخادم المشترك بداية للتطوير والاختبار؛ لا توجد بعد نتيجة تثبت سعة تشغيل المستخدمين أو استمرار الخدمة عند عطل المضيف. الانتقال إلى خادم أكبر لا يعادل توفرًا عاليًا تلقائيًا.

## نتيجة الفحص في 24 أكتوبر 2026

- Docker 29.8.0 وCompose v5.5.1 موجودان، وخدمة Docker مفعلة عند الإقلاع.
- الخادم يملك 4 معالجات افتراضية ونحو 7.6 جيجابايت ذاكرة؛ المتاح لحظة الفحص نحو 2.6 جيجابايت. مساحة القرص المتاحة نحو 23 جيجابايت، ولا توجد مساحة swap.
- حاوية `wainak-db-1` تعمل بحالة healthy. فحص الاتصال نجح، والمنفذ غير منشور، والشبكة داخلية، وحدا الذاكرة والمعالج مطبقان.
- استعادة نسخة قاعدة المشروع الحالية الفارغة داخل حاوية معزولة نجحت خلال نحو 4.18 ثانية.
- اختبار مستقل ببيانات اصطناعية نجح: استعادة النص العربي والمبالغ تمامًا، ورفض نسخة تالفة، ورفض الكتابة فوق قاعدة غير فارغة. حاويات وأقراص الاختبار المؤقتة أزيلت بعد الاختبار.
- خدمات البريد والموقع الموجودة بقيت قيد التشغيل، ولم يجر تعديل إعداداتها.
- لم ينفذ اختبار ضغط أو نقل إلى خادم ثانٍ، ولم تفعّل بعد نسخة خارجية أو واجهة تطبيق عامة. زمن تجربة البيانات الصغيرة لا يحدد زمن استعادة بيانات الإنتاج المستقبلية.
