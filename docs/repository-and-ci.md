# المستودع العام والتكامل المستمر

تاريخ التجهيز والنشر: 24 أكتوبر 2026. اختار صاحب المشروع حسابه الحالي، وأنشئ المستودع العام [dukkanai/wainak](https://github.com/dukkanai/wainak) وربط به `origin`. تحقق الوصول العام دون مصادقة وظهرت وظائف CI على GitHub. سجل الوظائف ونتيجة كل إصدار متاحان في [صفحة CI](https://github.com/dukkanai/wainak/actions/workflows/ci.yml).

## نطاق النشر

يشمل المصدر ووثائق المنتج والمراجعات والنموذج وملفات الاختبار وأدوات التشغيل. لا يشمل مجلدات `.runtime` أو `backups` أو `.codex` أو الاعتماديات أو نتائج الاختبارات المحلية أو حزم التسليم المولدة أو ملفات المفاتيح والبيئة الفعلية. بيانات المستخدمين وأدلة البلاغات المستقبلية لا تدخل المستودع أو اختبارات CI.

يفحص `scripts/check_publication.py` بايتات الملفات المضافة إلى فهرس Git نفسه، ويرفض مسارات التشغيل المستبعدة وبعض أنماط المفاتيح والرموز المعروفة، دون طباعة المحتوى المطابق. هذا فحص محدود يساند مراجعة الملفات، وليس ضمانًا لاكتشاف كل سر. يعمل ضمن CI، لكن CI يعمل بعد رفع الكود؛ يجب تشغيل الفحص محليًا قبل النشر أيضًا.

المستودع العام يتيح قراءة المصدر ووثائق المنتج. لم يضف هذا التجهيز ترخيصًا عامًا يمنح حقوق استعمال تجاري أو إعادة توزيع لكود المشروع. ترخيص الخط الخارجي محفوظ معه.

## ما يفحصه CI

ملف `.github/workflows/ci.yml` يعمل عند الدفع إلى `main` وطلبات الدمج، ويمكن تشغيله يدويًا. الوظائف الأربع هي:

1. `Source checks`: حدود النشر وأنماط الأسرار المعروفة وصياغة Python وJavaScript.
2. `Operations unit tests`: اختبارات أدوات التشغيل المحلية دون Docker حقيقي.
3. `Isolated database recovery`: اختبار Docker بقاعدة وقرص وأسرار وبيانات اصطناعية في مشروع مؤقت مستقل.
4. `Prototype browser tests`: تثبيت الاعتماديات من ملف القفل، وتجهيز HTML المستقل، وفحصه بالمتصفح وعينات الوصول.

تعمل جميعها على بيئات GitHub المستضافة والمؤقتة؛ لا يوجد runner ذاتي على سيرفر المشروع، ولا مفتاح SSH إليه، ولا خطوة نشر أو ترحيل قاعدة إنتاج. الاختبارات لا تحتاج أسرار حسابات أو متاجر أو خدمة فعلية.

الأذونات الافتراضية `contents: read`، ولا تحفظ بيانات اعتماد checkout، وتثبت الإجراءات الخارجية ببصمات commits كاملة. طلبات الدمج تستخدم `pull_request` دون `pull_request_target`، فلا ينفذ مصدر مساهم خارجي في سياق نشر ذي صلاحيات مرتفعة. إعداد Dependabot يقدم تحديثات أسبوعية للاعتماديات والإجراءات دون دمج تلقائي. هذه الضوابط تتبع [إرشادات GitHub لاستخدام Actions بأمان](https://docs.github.com/en/actions/reference/security/secure-use).

## طريقة العمل بعد النشر

أصبح `main` محميًا، وتنفذ التغييرات في فروع ثم طلبات دمج. قرئت إعدادات الحماية من GitHub بعد تطبيقها: تلزم الوظائف الأربع المذكورة أعلاه من تطبيق `github-actions` ذي المعرف 15368، مع تحديث الفرع قبل الدمج. يمنع الدفع القسري وحذف الفرع، وتلزم معالجة المحادثات المفتوحة وسجل خطي؛ تنطبق الحماية على المدير أيضًا. هذه إعدادات [حماية الفروع في GitHub](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches).

يلزم طلب دمج، لكن لا يشترط حاليًا اعتماد بشري من حساب ثانٍ، لأن المشروع يعمل بحساب مالك واحد. مراجعات الوكلاء ليست اعتماد GitHub من مراجع مستقل. يمكن إضافة هذا الشرط عندما ينضم مراجع مخول آخر.

فعّلت حماية الأسرار `secret_scanning` و`secret_scanning_push_protection`، وتحقق الإعداد من GitHub. لا يعني ذلك اكتشاف كل نوع من الأسرار. أذونات Actions الافتراضية للقراءة، ولا يسمح لرمزها باعتماد طلبات الدمج. لا يوجد نشر تلقائي إلى السيرفر.

لا يكفي نجاح تشغيل يدوي أو فحص commit قديم لقبول طلب دمج جديد. يربط سجل التحقق بنتيجة التشغيل والرأس المقصود ونوع الحدث. ولا تعني علامة نجاح CI قبول المتاجر أو نجاح الاتصال بين هاتفين أو اختبار قارئ شاشة فعلي.

## إعادة الفحوص محليًا

من جذر المشروع، بعد إضافة ملفات المصدر المقصودة إلى Git:

```bash
python3 scripts/check_publication.py
```

```bash
python3 -m unittest discover -s ops -p test_manage.py -v
```

```bash
python3 ops/test_recovery.py
```

من مجلد `prototype`:

```bash
npm ci --ignore-scripts --no-audit --no-fund
```

```bash
npm run package
```

```bash
WAINAK_PREVIEW_URL="file://$(pwd)/releases/wainak-preview.html" npm test
```

الاختبار يستخدم Chrome في `/usr/bin/google-chrome` افتراضيًا؛ يمكن تحديد مساره باستخدام `WAINAK_CHROME`. يبقى محتوى `prototype/releases` و`prototype/qa/results` محليًا ومولدًا، لذلك بعض روابط أدلة التسليم المحلية لا تكون موجودة داخل نسخة Git النظيفة حتى يعاد تجهيزها.

## نتيجة التجهيز المحلي

في 24 أكتوبر 2026 نجح فحص ملفات المصدر المعدة للنشر، ورفض اختبار الفاحص رمزًا اصطناعيًا داخل نسخة Git المضافة حتى عندما استبدلت نسخة العمل بنص آمن. رفض كذلك ملف تشغيل مضافًا عمدًا داخل مستودع مؤقت. هذه الاختبارات لا تقرأ أسرار المشروع الفعلية.

نجحت اختبارات أدوات التشغيل الـ21، واختبار Docker المعزول للمشروع المؤقت `wainak-test-be83f384`، وتأكد غياب حاويته وقرصه بعد التنظيف. نجحت أيضًا تجربة تصدير فهرس Git إلى مجلد مؤقت نظيف دون ملفات التشغيل: تثبيت الاعتماديات وتجهيز HTML و27 فحص متصفح وتسع عينات وصول. لم تسجل أخطاء صفحة أو طلبات HTTP خارجية في مسارات اختبار الواجهة.

فحصت بنية YAML والوظائف الأربع والأذونات وتثبيت الإجراءات بالبصمات. كانت هذه الفحوص محلية قبل النشر، ثم أضيف التحقق الحي الموضح أدناه. بقيت المسودة الأصلية وترخيص الخط كما هما، بما فيهما فراغات نصية تاريخية؛ لا يستخدم فحص التنسيق دليلًا على اختبار المنتج.

## سجل التحقق على GitHub

أول نسخة منشورة هي `b526539c778c516a64ab2b2c198ae10a9d900737`. شغلت حدث `push` على `main` في [التشغيل 40061831468](https://github.com/dukkanai/wainak/actions/runs/40061831468). حالة التشغيل الحية مرجع النتيجة، ولا يسجل تشغيل محلي بديلًا عنها.

يدخل تحديث التوثيق الحالي عبر فرع `chore/github-ci-bootstrap` وطلب دمج، لا عبر دفع مباشر إلى `main`. يفحص CI نسخة الدمج المقترحة بحدث `pull_request`، ثم يفحص إصدار `main` الناتج بحدث `push`. تقرأ نتيجة كل حدث ورأسه عند قبول التغيير.
