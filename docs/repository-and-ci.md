# المستودع العام والتكامل المستمر

المستودع العام هو [dukkanai/wainak](https://github.com/dukkanai/wainak)، على حساب صاحب المشروع، والفرع المعتمد `main`. مرجع حالة التسليم في [STATUS.md](STATUS.md)، ونتائج التشغيل في [GitHub Actions](https://github.com/dukkanai/wainak/actions/workflows/ci.yml).

## ما يدخل Git

المصدر والعقود والاختبارات والمواصفات والتراخيص والأقفال وتقارير الأدلة المنقحة. لا تدخل أسرار التشغيل أو قواعد البيانات أو النسخ الشخصية أو مخرجات البناء أو الكاش أو raw logs أو بيانات المستخدمين وأدلة بلاغاتهم.

يفحص `scripts/check_publication.py` بايتات فهرس Git نفسه، ويرفض مسارات مستبعدة وأنماطًا محددة من المفاتيح والرموز دون طباعة قيمها. يجب تشغيله قبل الدفع أيضًا؛ فحص CI يأتي بعد رفع المصدر، وهو فحص محدود لا يكشف كل سر محتمل. تحفظ المخرجات والأدلة الخاصة خارج Git.

المستودع العام يتيح قراءة الكود والوثائق. لم يعتمد ترخيص عام يمنح حقوق الاستعمال التجاري أو إعادة توزيع كود المشروع. تبقى تراخيص الخط والوحدات الخارجية محفوظة معها.

## وظائف CI في مرشح التكامل

وُسعت وصفة `.github/workflows/ci.yml` في دفعة 27 أكتوبر إلى تسع وظائف، تعمل على الدفع إلى `main` وطلبات الدمج والتشغيل اليدوي:

1. `Source checks`: حدود النشر وصياغة Python وJavaScript.
2. `Operations unit tests`: أدوات التشغيل واختبارات حدود تجميع HTML.
3. `Isolated database recovery`: استعادة بيانات اصطناعية داخل Docker مؤقت مستقل.
4. `Prototype browser tests`: تثبيت اعتماديات النموذج من القفل وتجهيز HTML وفحوص المتصفح والوصول.
5. `Backend contracts and tests`: اختبارات النطاق وAPI والعقود وضوابط المشغلات وصفحة الحذف.
6. `Authenticated matching integration`: حسابات وحذف ومطابقة على PostgreSQL معزول، مع ربط الاختبار بالـcommit نفسه وفحوص مستقلة.
7. `Flutter development tests`: SDK مثبت، وتحليل وhost tests، ثم الاختبارات المختارة والرحلات المحلية المتصلة صراحة. النتائج المتخطاة في التشغيل الافتراضي لا تحسب قبولًا للرحلات المتصلة.
8. `Archive and bridge tests`: وحدات Go والأرشيف والتوافق والاختبارات المستقلة وكاشف السباقات، مع فحص بقاء الأقفال دون تغيير.
9. `Native build guard tests`: صحة الإعدادات والمصدر وضوابط الموارد والعمليات والتشخيص والتحقق من النتائج. هذه وظيفة Linux؛ لا تبني Android أو iOS ولا تشغل جهازًا.

نجحت الوظائف التسع فعليًا على نسخة المصدر `4d0d75c` في [التشغيل 40444381675](https://github.com/dukkanai/wainak/actions/runs/40444381675)، ووثق [إيصال القبول](evidence/unification-ci-20261027.json) الرأس والأساس والشجرة. تبقى فحوص آخر التزام في [طلب الدمج 2](https://github.com/dukkanai/wainak/pull/2) ثم `push` على ناتج الدمج هي مرجع النسخة النهائية، وحالتها في [STATUS.md](STATUS.md).

## الصلاحيات والموارد

جميع الوظائف على GitHub-hosted runners مؤقتة. لا يوجد runner ذاتي على سيرفر wainek أو مفتاح SSH إليه أو خطوة نشر إنتاجي. تعتمد الاختبارات حسابات وبيانات وقواعد مؤقتة، ولا تحتاج مفاتيح متجر أو مزود بريد أو قاعدة تشغيل.

صلاحيات Actions الافتراضية `contents: read`، ولا يحتفظ checkout ببيانات اعتماد. الإجراءات الخارجية مثبتة ببصمات commits، والحزم بأقفالها أو بصماتها المعلنة. يستخدم PR الحدث `pull_request`؛ لا يوجد `pull_request_target` ينفذ مصدر مساهم في سياق نشر ذي صلاحيات مرتفعة. Dependabot يقترح التحديثات، ولا يدمجها تلقائيًا.

وصفة Codemagic منفصلة ويدوية للبناء الأصلي. لا يبدأها CI أعلاه، ولا يثبت نجاح Linux قبول Apple. حدودها في [دليل البناء](../ci/README.md).

## الفروع والحماية

كل تغيير على فرع قصير العمر ثم طلب دمج. يمنع الدفع القسري وحذف `main`، وتطبق الحماية على المدير. يجب أن تكون اختبارات النسخة المطلوبة من تطبيق GitHub Actions نفسه، وأن تكون محدثة مع الأساس، وأن تحسم محادثات المراجعة المفتوحة قبل الدمج.

وُسعت حماية `main` فعليًا في 27 أكتوبر لتتطلب الوظائف التسع من تطبيق GitHub Actions رقم `15368`، مع اشتراط تحديث الفرع وفق الأساس. قُرئت الإعدادات من GitHub بعد التعديل؛ نجاح جميع الوظائف على نسخة طلب الدمج ما زال شرطًا مستقلًا قبل الدمج. لا يشترط حاليًا اعتماد بشري من حساب ثانٍ لأن المشروع يدار بحساب مالك واحد؛ مراجعة الوكلاء ليست اعتماد GitHub بشريًا مستقلًا.

كان secret scanning وpush protection مفعّلين عند آخر فحص 27 أكتوبر. هذه ضوابط مساندة لا تكشف كل سر. قواعد الحماية والإعدادات الخارجية قابلة للتغير، فتراجع عند التسليم أو تعديل مسار الدمج.

## معيار القبول

يرتبط الدليل بنوع الحدث ورأس المصدر وأساس الدمج وشجرة النسخة ونتائج الوظائف المطلوبة. لا يكفي تشغيل يدوي أو نجاح commit قديم لقبول PR جديد، ولا تستبدل نتيجة محلية بنتيجة GitHub المطلوبة. بعد الدمج يتابع فحص `push` على commit الناتج.

لا تعني علامة CI ناجحة قبول المتاجر أو نجاح المراسلة بين هاتفين أو فحص قارئ شاشة فعلي أو جاهزية الإنتاج. أوامر إعادة الفحص المحلية في [DEVELOPMENT.md](DEVELOPMENT.md).
