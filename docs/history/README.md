# سجل المراحل والأدلة التاريخية

الحالة الحالية في [STATUS.md](../STATUS.md)، وطريقة التطوير الحالية في [DEVELOPMENT.md](../DEVELOPMENT.md). هذا الدليل يوضح كيف تقرأ السجل القديم دون أن تخلطه بحالة المنتج الآن.

## ما نحتفظ به ولماذا

- `docs/phase*.md`: نطاق كل مرحلة وتصميمها وقيودها وقت التنفيذ.
- `docs/reviews/phase*.md` و`docs/reviews/stage*.md`: مراجعات واختبارات مرتبطة بنسخ معينة؛ وجود PASS فيها لا يثبت قبول commit لاحق.
- `docs/ci/*diagnostics*.md` وتقارير محاولات البناء: تشخيص المحاولات السحابية السابقة وما ترتب عليها.
- `docs/draft.md`: المسودة الأولى؛ القرارات الأحدث في فهرس المواصفات تتقدم عليها.
- [ملخص الأدلة المحفوظة](../evidence/legacy-verification-20261027.json): نتائج آمنة وبصمات أدلة محلية قبل تنظيف مجلدات التجارب.
- [سجل التنظيف](cleanup-20261027.md): نطاق الاحتفاظ والحذف وما لم ينفذ بعد.

تبقى أسماء التقارير ومساراتها مستقرة لحفظ روابط المراجعة. أضيف تمييز تاريخي إلى التقارير القديمة بدل نقلها عشوائيًا أو حذف الأدلة المفيدة. بعض الملفات تسجل أن APK أو Flutter أو Codemagic لم يكن موجودًا آنذاك؛ لا تؤخذ العبارة وصفًا للحالة الحالية.

## حدود الأدلة

تاريخ الاختبار ومصدره وأدواته وبيئته جزء من النتيجة. قبول نموذج HTML يختلف عن Flutter، واختبار widget أو HTTP محلي يختلف عن تشغيل هاتف، وبناء `build-for-testing` لا يشغل XCTest. والأرشيف المشفر لا يثبت وجود مراسلة مشفرة.

بعض أدوات إعادة الاختبار القديمة كانت مرتبطة بمسارات خاصة في مضيف التجربة أو بملف حُذف لاحقًا. أزيلت أدوات التشغيل المتروكة، مع إبقاء اختبارات Go والنتائج التاريخية. تستخدم الأوامر الحالية في [دليل التطوير](../DEVELOPMENT.md)، ولا تنسخ أمرًا قديمًا دون فحص تبعياته.

لا تنشر السجلات الخام أو بيئة المضيف أو أسرار الاختبارات. حفظ بصمة ملف لا يثبت وحده صحة محتواه أو مصدره. عند نقل نتيجة إلى النسخة الموحدة يعاد تشغيل الفحص المطلوب على تلك النسخة وتوثق النتيجة الجديدة.
