## قرار المكدس وحدوده

**تفصيل تنفيذي:** Python 3.11+، منطق مجال منظم، محول JSON/WSGI للتجربة المحلية فقط،
وOpenAPI 3.1 عقدًا مستقلًا عن اللغة لتطبيق Flutter. لا توجد اعتماديات خارج المكتبة
القياسية أو خطوات تنزيل. اختبر على Python 3.14.4 الموجود في السيرفر.

السبب: قواعد الأهلية والموافقة والحظر أهم موضع نحتاج تثبيته قبل ربط المصادقة والدفع
والاتصال. يتيح ذلك اختبارات حتمية وسريعة، ويجنب إدخال إطار ومخزن بيانات وخدمة جديدة
على سيرفر مشترك لمجرد عرض مسار تجريبي. Python مستخدم أصلًا في أدوات المستودع؛ وعقد
JSON لا يفرض لغة على Flutter.

هذه ليست توصية باستعمال `wsgiref` للإنتاج. ليس له هنا TLS أو دفاع تشغيلي من الاستنزاف
أو تقييد معدلات أو استرداد حساب أو عامل مهام. اختيار خادم الإنتاج/إطار HTTP وترخيصه
وتثبيت اعتمادياته وفحصها يأتي مع محول PostgreSQL والمصادقة الحقيقية. تبقى PostgreSQL
مصدر الحقيقة المستهدف كما في التصميم المعتمد؛ لم نبدلها بقاعدة أخرى.

## فصل الصلاحيات والموافقات

معرف الفاعل يأتي من الجلسة، وليس من حقل يرسله العميل. لا تقبل الخدمة حقولًا إضافية
مثل `actor_id` أو `photo` أو `conversation`. معرفة معرف العلاقة لا تمنح قراءتها؛
الطرف الثالث يحصل على 404 عامة. المرسل لا يقبل دعوته ولا يقبل اقتراح حصرية قدمه.

قبول التعارف لا يفعله دون خطوة الاستحقاق المحاكاة. التفعيل المتأخر يعيد قراءة الحالة
الحالية ولا يتجاوز الحظر أو الإنهاء أو بلوغ أربع زوجات. الحصرية لا تفتح النص أو الصور
أو الهوية؛ تظل أذوناتها كلها `false`. لا يوجد مسار انتقال إلى الخطبة/الزواج بعد، ولا
مسار يدعي إرسال محتوى شخصي. بطاقات المكتبة المجانية المعادة هي محتوى مؤلف، لا أجوبة.

الحظر والإبلاغ متاحان قبل الدفع. لا يغير الحظر أو حذف الرابط إقرار الحالة الاجتماعية
أو عدد الزوجات. البلاغ لا يعاقب الحساب الآخر؛ هو سجل اصطناعي واضح لا يصل لفريق حقيقي.
لا يستطيع الشخص منع بلاغ مرشح يعرفه بحظره أولًا؛ يبقى الإبلاغ ممكنًا في الاتجاهين،
دون إعادة كشف الملف أو فتح التواصل. أضيف هذا الضابط بعد اختبار مستقل كشف النقص.
يبقى D25 معتمدًا، لكن الرفع مرفوض حتى تنفذ المعاينة والموافقة والنطاق ومخزن الأدلة
المعزول وصلاحيات المراجع والاحتفاظ والحذف. لا يعاد فتح هذا القرار طلبًا لموافقة جديدة.

## اتساق النموذج وحدود الإثبات

تُسلسل كل قراءة وتغيير داخل `RLock` واحد لكل نسخة خدمة، وتُنسخ النتائج عند إخراجها؛
تغيير العميل لكائن أعيد إليه لا يغير مخزن الخدمة. تتنافس طلبات الحصرية فعليًا عبر خيطين
في الاختبار؛ ينجح واحد فقط. إعادة طلب التعارف بنفس المفتاح تعيد **حالته الحالية** حتى
بعد الحظر. تغيير المرشح مع إعادة المفتاح يفشل، والمفتاح معزول بحسب الفاعل.

هذه ذرية **عملية واحدة في الذاكرة فقط**. تشغيل عمال مستقلين سيخلق مخازن مستقلة؛ لا يجوز
نشر هذا المحول أو الادعاء أن قيد قاعدة البيانات/السباق بين خادمين اختبر. محول PostgreSQL
التالي يحتاج قيودًا ومعاملات واختبارات تنافس على قاعدة اصطناعية منفصلة، لا قاعدة السيرفر.

الجلسة رمز عشوائي مؤقت، لا تحفظ بصورته الصريحة داخل مخزن الجلسات؛ تعاد مرة للعميل.
لا توجد صلاحية زمنية/تجديد/استرداد بريد إنتاجية بعد، وتبطل بالحذف أو نهاية العملية.
لا تحتوي المستودعات على رموز ثابتة أو أسرار أو مستخدمين حقيقيين. لا يوجد تسجيل لمحتوى
الطلبات أو رموز الجلسات، ولا رسائل خطأ تعكسها. هذا ليس ضمانًا لأمن كل تسجيل مستقبلي.

## تحديث المرحلة 1.1: استمرارية PostgreSQL اختبرت في عزل حقيقي

أضيفت واجهة `Repository.transaction()`، وتنفيذ ذاكرة بنسخ عند الكتابة، ومحول اختياري
بـPsycopg 3.3.6 مثبت الإصدار والبصمة. بقيت واجهة API وCLI افتراضيًا في وضع الذاكرة

المشروع بالقاعدة الموجودة، ولا تنشئ خدمة أو صلاحية أو منفذًا عامًا.

المهاجرة في `backend/wainak/migrations.py` أثر مصدر مراجَع، لا فعل تلقائي عند بدء API.
تحتاج تفويض اختبار صريحًا، وترفض اسم قاعدة خارج حيز الاختبارات العشوائية وترفض قاعدة
تحتوي مخطط مستخدم سابقًا. يحمي المحول علامة إصدار ونمط اصطناعي قبل قراءة بياناته.

تحفظ الجداول الحسابات والموافقات منفصلة والعلاقات والحصرية والحظر والبلاغات الوصفية
ومفاتيح منع التكرار وبصمات الجلسات. لا يوجد مخزن محادثات أو صور أو أدلة. يقفل المحول
معاملة PostgreSQL عبر advisory lock، ثم يقرأ ويتحقق ويحفظ ذرّيًا؛ لا يكتفي بقفل Python.
وتمنع قيود DB ازدواج زوج العلاقة، وازدواج مفتاح طلب الفاعل، ووجود حصرية ثانية للحساب.
تتحقق قيود مؤجلة من طرفَي الحصرية في الحالة النهائية للمعاملة.

يستبدل هذا المحول لقطة صغيرة كاملة داخل المعاملة بهدف إثبات الصحة أولًا. **هذا قيد
أداء معروف، وليس طبقة إنتاج قابلة للتوسع.** يلزم لاحقًا استعلام محدود وصفوف مقفلة
وفهارس/مهاجرات متدرجة وحساب تشغيل محدود وقياس الضغط، مع الحفاظ على اختبارات السلوك.

يشغّل `backend/integration/run_postgres.py --run-disposable-postgres` حاوية وvolume
جديدين موسومين باسمه العشوائي، بالصورة الرسمية المثبتة الموجودة دون سحبها، وبدون شبكة
أو منافذ منشورة. الاتصال عبر Unix socket داخل مجلد مؤقت خاص، والسر اصطناعي مؤقت لا
يكتب للمستودع ولا يطبع. بعد الاختبار يتحقق من label قبل حذف موارده وحدها، ثم يتحقق من
غياب الحاوية والقرص والمجلد المؤقت. خطأ فحص Docker لا يحسب دليلًا على حذف ناجح.

الاختبار الأول الحقيقي نجح: **12/12 على PostgreSQL 17.11**، مع إعادة تشغيل الحاوية
فعليًا والتحقق من بقاء البيانات، وسباق حصرية من عمليتين مستقلتين، وعشرة سباقات حظر
وتفعيل، وتراجع كامل عند فشل قيد، ومنع SQL injection بالمعاملات، واستمرار الحذف وإلغاء
الجلسة. استغرق 23.583 ثانية وتحقق التنظيف. أضيفت أربعة اختبارات للواجهة الجديدة فأصبح
اختبار الذاكرة/API والعقد 46 اختبارًا. يعاد التحقق على الرأس النهائي وتراجع نتائجه
مستقلًا؛ الأرقام هنا لا تستبدل سجل قبول الـcommit.

تفاصيل إعادة الاختبار والعزل والحدود في [دليل PostgreSQL المعزول](../backend/integration/README.md).
يبقى غير منفذ: ترحيل قاعدة التشغيل، أدوار ومصادقة إنتاج، انتهاء/تجديد الجلسات، سجلات
احتفاظ وحذف إنتاجية، تشفير النسخ، ضغط وتوسع، دفع ومراسلة حقيقية أو قبول متاجر. لم تعد
«عدم اختبار PostgreSQL إطلاقًا» وصفًا صحيحًا لهذه النسخة؛ الصحيح أنه اختبر **في قاعدة

## تحديث المرحلة 1.2: سلسلة Flutter وHTTP وقاعدة معزولة

أضيف `backend/integration/run_flutter_postgres.py` لتجميع الرحلة نفسها بدل الاكتفاء
بفحوص Flutter وPostgreSQL منفصلة. يبدأ بـ14 اختبار PostgreSQL، ثم يشغّل عملية WSGI
جديدة على loopback ومنفذ مؤقت، ويمرّر للـFlutter عنوان HTTP فقط؛ لا DSN ولا سر قاعدة.
يحتاج تفعيلًا صريحًا وأدوات مشروع موجودة، ولا يثبت SDK أو يغير صلاحية أو حد ذاكرة.

يتوقف العميل عند نقطتي علاقة مفعلة وعلاقة محظورة. عبر ملفات تحكم محلية ثابتة غير
سرية، يوقف المشغّل عملية التطبيق ويعيد تشغيل قاعدة الاختبار وحدها ثم يبدأ عملية
تطبيق جديدة على المنفذ نفسه. يحتفظ العميل بالجلستين في الذاكرة ويتحقق من الحسابات
والحالة والبطاقات والحظر والبلاغ والحذف؛ لا يعوض فقدان الجلسة بإنشاء حساب جديد.
نجاح بلا نقطتي إعادة التشغيل يعتبر فشلًا. لا توجد نقطة إدارة أو restart في API.

يقيد المشغّل بيئة Flutter، ويتحقق من ملف الاختبار وملفات التحكم وملكيتها ومواضعها،
ويرفض symlink escape/FIFO والتحكم بمحتوى غير متوقع. يوقف مجموعة عمليات الطفل
وعملية WSGI حتى عند إخفاق cleanup الجزئي، ثم يتحقق المشغّل المحيط من حذف حاويته
وvolume والمجلد المؤقت فقط. تغطي اختبارات خفيفة هذه الضوابط، ومنها خروج الطفل
بين فحص حالته وإرسال الإشارة، ورفض جذر test/ المرتبط خارج نسخة التطبيق.

يمكن لـQA اختيار اختبار widget محلي مراجَع في نسخته المعزولة عبر `--test-file`،
دون تعديل شجرة مطور الواجهة. لا يُقبل shell أو URL أو ملف خارج test/؛ يسجل الاختبار
بصمة المصدر وإصدارات الخلفية والواجهة وعلامات الشجرة المتغيرة. دليل التشغيل
والحدود في [دليل السلسلة الموحدة](../backend/integration/FLUTTER_CHAIN.md).
