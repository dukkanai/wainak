# wainek: إعداد الاختبار الداخلي على TestFlight

تاريخ الإعداد: 29 أكتوبر 2026. هذه وصفة معدّة محليًا، وليست دليل بناء أو رفع أو قبول VoiceOver على iPhone. التشغيل السحابي والرفع إلى Git يحتاجان مراجعة المستخدم وموافقته التالية.

## الهوية ومراجع التوقيع

أكد المستخدم من واجهة Apple وCodemagic:

- اسم العرض: `wainek` حرفيًا.
- Bundle ID: `com.nextaura.wainek`، واختبارات Runner: `com.nextaura.wainek.RunnerTests`.
- الفريق: `NEXTAURA LLC`، بمعرف `9G7GPBG7FB`.
- سجل App Store Connect القائم: `6828249128`. لا ينشأ سجل بديل.
- SKU التاريخي الثابت: `WAINAK-IOS-001`. يبقى كما هو.
- مرجع الشهادة: `nextaura_apple_distribution`.
- مرجع ملف App Store: `wainek_app_store`، مطابق للشهادة والفريق والحزمة. أكد المستخدم انتهاء كليهما في 29 أكتوبر 2027.
- اسم اتصال API الفعلي: `Codemagic Wainak`. لا يغيره المصدر إلى اسم مفترض.

تستخدم الوصفة مرجعَي الشهادة والملف صراحةً، دون البحث عن بديل أو إنشاء شهادة أو ملف أو مفتاح. لا يوجد ملف Apple أو سر في المشروع. الإعداد يطابق [صيغة Codemagic لاختيار ملفات التوقيع بالمرجع](https://docs.codemagic.io/yaml-code-signing/signing-ios/#fetching-specific-files-by-reference-names).

## نطاق النسخة وحدود التوزيع

الوصفة `ios-testflight` منفصلة عن وصفتَي unsigned. تفتح الواجهة عبر `WAINEK_DEV_MODE=true` و`WAINEK_REPOSITORY=fake` ببيانات اصطناعية في الذاكرة. لا تفعّل حسابات حقيقية أو دفعًا أو مراسلة أو جسر الأرشيف الأصلي. اسم المنتج الجديد لا يحوّل النموذج إلى تطبيق إنتاجي.

إعداد التصدير `testFlightInternalTestingOnly=true` يحصر الملف بالمختبرين الداخليين. النشر المعدّ إلى App Store Connect يستخدم الاتصال القائم؛ `submit_to_testflight=false` يمنع الإرسال إلى مراجعة الاختبار الخارجي، و`submit_to_app_store=false` يمنع تقديمه للإصدار العام. لا مجموعات خارجية أو نشر تلقائي عند push. [توثيق Codemagic للنشر](https://docs.codemagic.io/yaml-publishing/app-store-connect/) يشرح الفرق بين رفع الملف وإرساله للمراجعة.

الحواجز تفحص هوية المستودع السحابي، التشغيل اليدوي، الالتزام النظيف، نسخ Flutter وXcode المثبتة، الأعلام الفعلية، خيارات التصدير، بنية IPA، التوقيع، الفريق، الحزمة، صلاحية ملف التوزيع ومعمارية arm64. لا يصبح ملف IPA مؤهلًا للنشر إلا بعد اكتمال الفحوص. محاكاة المسار محليًا تختبر نجاحه ورفض التوقيع أو الفريق أو المعمارية أو خيارات التوزيع الخاطئة؛ لا تستبدل تنفيذ أدوات Apple فعليًا.

الفحوص الأمنية لوصفات unsigned تبقى قائمة، بما فيها رفض توقيع ad hoc. هذه الدفعة لا تدّعي معالجة فشل المحاكي السابق على Xcode دون إعادة تشغيل معتمدة.

## بعد مراجعة النتائج المحلية فقط

1. يراجع المستخدم الفرع والالتزام والنتائج؛ بعدها يوافق صراحةً على دفع الفرع، دون دمج main.
2. بعد موافقة مستقلة على البناء والرفع، يختار المشغل الفرع والالتزام نفسيهما ووصفة `ios-testflight` في Codemagic. تشغيل هذه الوصفة يتضمن رفع الملف المتحقق منه إلى App Store Connect.
3. إذا اختلف اسم اتصال API لاحقًا، يحدّث الاسم الدقيق في الوصفة والسياسة واختباراتهما قبل تشغيلها.
4. بعد نجاح معالجة Apple، تضاف النسخة إلى الاختبار الداخلي فقط، ثم يختبر المستخدم التنقل والتركيز والنطق وتكبير النص وVoiceOver على جهازه.

لا يوجد الآن دليل على إنشاء IPA من هذه النسخة أو تشغيلها على iPhone. صلاحية الهوية والملف والشهادة هنا معلومات مؤكدة من المستخدم؛ سيفحص البناء الفعلي محتويات الملف والتوقيع عند تشغيله المصرح به.
