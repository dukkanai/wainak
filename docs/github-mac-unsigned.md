# wainek: تشغيل Mac القياسي على GitHub دون توقيع

تحديث 29 أكتوبر 2026 بعد تغيير المستخدم وجهة الاختبار. لا تشغيل خامس على Codemagic. هذا المسار جاهز للمراجعة والتشغيل اليدوي على فرع `dev/ios-testflight-internal-20261029`؛ تجهيز الملف واختباره محليًا لا يعني تنفيذ Mac أو نجاح البناء عليه.

## الحدود

المستودع العام `dukkanai/wainak` وActions مفعّل، وقد تحقق ذلك بقراءة GitHub API دون تعديل صلاحياته. تستخدم المهمة `macos-26` القياسي فقط: arm64، ثلاث أنوية، 7 GB ذاكرة و14 GB تخزين بحسب [توثيق GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners). الأجهزة القياسية مجانية للمستودعات العامة. لا اختيار ديناميكي لجهاز، ولا large أو self-hosted، ولا ترقيات أو أسرار Apple أو نشر artifacts أو IPA أو TestFlight.

تعرض [صورة GitHub المنشورة](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md) Xcode 26.4.1 build 17E202 في `/Applications/Xcode_26.4.1.app`. الصورة تتغير؛ لذلك نحدد `DEVELOPER_DIR` ونتحقق من الإصدار الحقيقي قبل تنزيل SDK. نثبت Python 3.12.7 للمقارنة مع Codemagic. نظام التشغيل الدقيق والمساحة الفعلية لا يمكن إثباتهما قبل تخصيص الجهاز؛ يسجلهما المسار ويغلق عند اختلاف المعمارية أو نقص الموارد.

صلاحية المهمة `contents: read`، وcheckout دون حفظ credentials. أوامر البناء تعمل ببيئة مسموحة محدودة؛ لا تمرر رموز GitHub أو Apple. لا تُطبع stdout أو stderr أو الاستثناءات الخام. يبقى الرصد الآمن والأخطاء المحدودة، ويفشل أي تنظيف غير مثبت.

## اختيار المهمة دون دمج main

أضفنا خيارًا يدويًا إلى ملف `.github/workflows/ci.yml` المسجل أصلًا في الفرع الافتراضي. يبقى push مقتصرًا على main، وتبقى فحوص pull_request القائمة كما هي. اختيار `target=mac-unsigned` يعطل المهام التسع الأخرى لهذا التشغيل اليدوي فقط. المهمة الجديدة تشترط المستودع العام الصحيح، والفرع المحدد، وSHA كاملًا مطابقًا للحدث. اختيار `ci` يبقي المسار السابق.

المشغل يراجع SHA النهائي، ويتأكد أنه رأس الفرع البعيد، وأنه لا توجد محاولة لنفس SHA قيد التشغيل. ثم يرسل workflow_dispatch لملف `ci.yml` على الفرع مع `target=mac-unsigned` و`expected_sha` المطابق. قد لا تعرض واجهة GitHub مدخلات الفرع غير الافتراضي؛ يمكن للمشغل استخدام CLI/API مع ref الفرع دون تعديل main. لا يفترض نجاح dispatch قبل استجابة GitHub، ولا يستبدل required checks على PR.

الحد 45 دقيقة للمهمة، و40 دقيقة داخل السائق. حارس ابتدائي يتطلب 10 GiB متاحة قبل التنزيل، ثم 4 GiB كحد أدنى و8 GiB حدًا منطقيًا لمساحة SDK والعمل والبناء المملوكة للمهمة. هذه مراقبة وليست quota على نظام الملفات؛ لا يحذف المسار أدوات الصورة لتوفير مساحة. إذا لم تكفِ المساحة يتوقف، ولا ينتقل تلقائيًا إلى جهاز مدفوع.

## التسلسل

1. التحقق من الحدث والفرع وSHA ونظافة المصدر والمستودع العام والمضيف والقرص.
2. فحص النشر وتحضير المصدر واختبارات السياسة، ثم التحقق من Xcode.
3. تنزيل أرشيف Flutter macOS arm64 المثبت في `ci/ios-host-pins.json`، بحد حجم ووقت وقرص، والتحقق من SHA-256 قبل الاستخراج. حذف الأرشيف الذي أنشأته هذه المهمة فقط بعد نجاح الاستخراج.
4. التحقق من نسخ Flutter وDart وengine والتزام مصدر SDK، ثم إعداد نسخة التحليل المعدلة والمثبتة بالبصمات. تشغيل أحد عشر اختبار انتظار عبر Dart، منها عمليتان حقيقيتان وحالة تجاهل TERM.
5. تنزيل حزم التطبيق مع enforce-lockfile، والتحليل المعدل، واختبار مدخل الواجهة التجريبية fake.
6. بناء iOS للجهاز arm64 دون توقيع. إعداد xcconfig مستقل يرفض التوقيع، ولا ملفات توزيع أو keychain أو أدوات رفع. فحص الناتج بالحارس القائم `ci/ios/check_unsigned.py` الذي يرفض ad hoc أيضًا، وفحص المعمارية وبقاء الملفات المتتبعة دون تغيير.
7. إعلان نجاح compile فقط مع SHA للمصدر والتنفيذ. لا يُرفع ملف التطبيق كـartifact، ولا يثبت ذلك تشغيله أو VoiceOver أو وظائف إنتاجية.

## تصحيح SDK والأدلة

يحدد `ci/testflight/sdk_delta/manifest.json` الالتزام الأصلي وSHA-256 للمصدر قبل التعديل وبعده ودالة الانتظار وطريقة الاستبدال. التعديل محصور في `analysis.dart`: ينتظر الأب خروج خادم التحليل وجمعه لمدة خمس ثوان، ثم يحاول الإنهاء القسري وانتظار ثانيتين عند تجاوز المهلة. تجاوز المهلة أو فشل الإشارة أو تعذر إثبات الخروج يظل فشلًا حتى إن نجح التنظيف اللاحق.

ينسخ `ci/testflight/sdk_overlay.py` ملفات flutter_tools المتتبعة المتحقق منها إلى مجلد عمل مستقل. لا يغير SDK الأصلي أو لقطة flutter_tools.snapshot. يشغل أمر analyze من المصدر مباشرة عبر Dart الأصلي مع package_config مشتق من تجهيز مستقل ومقيد بملف القفل للنسخة المنسوخة. تتحقق بصمات المصدر والنسخة المشتقة قبل أوامر Flutter وبعدها. حزم أدوات Flutter ومحتوى cache خارج المصدر تظل ضمن ثقة SDK المجهز؛ أرشيف GitHub الكامل مثبت ببصمته قبل استخدامه.

أثبتت تجربتان محليتان على Flutter الفعلي في Linux، مع نموذج errno خاص بـDarwin وجامع توابع داخل الاختبار فقط، خروج analyze برمز صفر وإخراج 96 بايت وبقاء مجموعة العمليات فارغة قبل التنظيف، دون أخطاء تنظيف. لا يُستخدم جامع التوابع التجريبي في الإنتاج، ولا تثبت المحاكاة سلوك نواة Mac. لم تُثبت عضوية المجموعة في البناء الرابع الحقيقي؛ تفسير التوابع المنتهية مرجح وليس فحصًا مباشرًا لذلك المضيف.

يرصد التنفيذ المجموعة قبل التنظيف وبعده بواسطة ps محدود المهلة والحجم: أعداد الأعضاء والمنتهين والأحياء والحالات غير المعروفة، وعدادات الملكية والأب init والابن القائد. لا ينشر أرقام العمليات أو أسماءها أو سطور أوامرها أو البيئة. اللقطات ليست إثباتًا لغياب مجموعة العمليات؛ يبقى killpg والتحقق الحاليان مصدر قرار التنظيف. فشل تنظيف عملية الرصد ذاتها يرفض التنفيذ. لا يتحول EPERM إلى نجاح حتى إذا عرضت اللقطة صفر أعضاء.

المتبقي غير المثبت: تنفيذ المسار على GitHub Mac، ملاءمة المساحة الفعلية، تجميع Xcode وغياب التوقيع في الناتج، وتشغيل الواجهة وVoiceOver على جهاز. لا يُنسب الفشل القديم غير المشخص إلى هذا السبب دون دليل مستقل.

## معالجة فشل التجهيز في GitHub 40839666566

أُعيد فحص سجل المحاولة على `bc8d3bbb9e7a86f53045210f3bcccd231ff0abe6` مباشرة. اجتازت الحواجز و369 اختبار سياسة وXcode وبصمة الأرشيف ونسخة Flutter وقراءة HEAD وجرد Git، ثم فشلت قبل التحليل. لم تكن المساحة السبب: سجل المضيف 102685982720 بايت متاحة.

نُزّل أرشيف macOS نفسه محليًا، بحجم 2267355570 بايت، وثبت SHA-256 الكامل `6114edc2dae3636cfefb7e4456a4510399ee856e324149b34dbacb509e329d05`. جميع ملفات المصدر المحددة البالغ عددها 1462 تطابق blobs الالتزام المثبت، دون نقص أو انحراف أو تصادم أسماء عند تجاهل حالة الأحرف. الأرشيف يحتوي `bin/cache/flutter_tools.snapshot`، ولا يحتوي أي ملفات `packages/flutter_tools/.dart_tool/`. ملف القفل موجود وبصمته `6a98afb61c0cc72f31631ab444932f072fd275aa04d56cde2bf6831ba02fc8f8`؛ يطابق الملف المحلي أيضًا.

أعادت نسخة الكود القديمة إنتاج `sdk_regular_file` على هذه المدخلات بعد اكتمال snapshot ونسخ المصدر، عند محاولة قراءة package_config غير الموجود. نجاح `flutter --version` لا يضمن إنشاء هذا الملف؛ أداة Flutter تستطيع تشغيل لقطة التنفيذ الجاهزة دون إعادة حل حزم مصدرها. الاختبارات السابقة اعتمدت بيئة محلية سبق تجهيزها، ومحاكاة للسائق لم تختبر غياب إعداد حزم SDK الحقيقي. هذا هو نقص التغطية الذي عولج، وليس فشلًا في خادم التحليل نفسه.

النسخة الجديدة تنسخ ملف قفل أدوات Flutter المتحقق من بصمته إلى النسخة المعزولة، وتشغل Dart الأصلي بالأمر `pub get --enforce-lockfile --no-precompile` داخلها. لا upgrade، ولا حذف لقطة SDK أو تغيير ملفات المصدر الأصلية لإجبار bootstrap. يُفحص ثبات القفل والمصدر، وتُجمّد ملفات package_config وpackage_graph المولّدة وباقي النسخة؛ أي ملف زائد أو رابط رمزي أو انحراف يرفض التنفيذ. كان هذا الإصدار يثبت وجود أو غياب package_config في SDK الأصلي قبل تهيئة cache؛ كشفت المحاولة التالية أن هذا التوقيت غير صحيح، وصُحح كما هو موضح أدناه.

أضيفت أحداث `SDK_OVERLAY_STAGE` بمراحل ثابتة من جرد المصدر حتى التحقق النهائي، مع أسباب سياسة محددة مسموح بإظهارها، دون نص الاستثناء أو المسارات. تغطي الاختبارات كتالوج كل حراس SDK، وغياب الإعدادات، وحالتي SDK المجهز وغير المجهز، وتغير القفل والمصدر، وفشل تجهيز الحزم والروابط الرمزية والأسماء المتصادمة.

قيمة `checkout_resolves_to_root=false` في المحاولة كانت خطأ عرض مستقلًا: دالة مشتركة قرأت CM_BUILD_DIR رغم أن السائق تحقق بالفعل من GITHUB_WORKSPACE. تقرأ الآن سياق GitHub الصريح، وتستخدم بيئة الأمر الفعلية عند إعلان PUB_CACHE. الحارس الأصلي لا يتغير: يقبل alias للمسار نفسه ويرفض مجلدًا آخر. عدم حساسية قرص Mac للأحرف ليس تفسيرًا لفشل هذه المحاولة؛ الجرد المثبت لا يحوي تصادمات، ويُرفض أي تصادم جديد صراحةً قبل النسخ.

نجح تجهيز مصدر الأرشيف غير المجهز مع ذاكرة حزم محلية فارغة، ثم اختبارات الانتظار الأحد عشر والتحليل عبر Dart على Linux. لكن مراجعة المحاولة التالية أثبتت نقصًا في هذه التجربة: pub_get استخدم SDK المحلي المجهز، بينما تحقق الحارس من نسخة المصدر الأخرى؛ لذلك لم تثبت التجربة ثبات إعداد SDK نفسه عبر المسار الكامل. هذه تجربة لمصادر macOS الفعلية باستخدام تنفيذ Dart الخاص بـLinux؛ لا تدّعي تشغيل ثنائيات macOS أو Xcode. يبقى تشغيل الالتزام الجديد على GitHub Mac خطوة المشغل التالية بعد المراجعة.

## تهيئة cache قبل تثبيت المرجع: GitHub 40841861518

اجتاز الالتزام `bda1e18c00e6a12cc5a3ff71b90580d7c5d77470` تجهيز النسخة المعزولة واختبارات انتظار Dart الأحد عشر على Mac. نجح أمر التطبيق pub_get برمز صفر و351 بايت ودون فشل تنظيف، لكن التحقق اللاحق رفض `sdk_package_config_changed`. سجل المحاولة لا يحوي محتوى الملف أو بصمته بعد الأمر؛ لذلك لا ننسب بصمات التجربة المحلية إلى ملف المضيف السحابي.

في مصدر Flutter المثبت، `PubDependencies.isUpToDate` في `flutter_cache.dart` يفحص وجود إعداد أدوات Flutter ووجود حزمها. تنفذ `_updateCacheAndRunPubGet` في `flutter_command.dart` تحديث universal cache قبل أمر التطبيق. إذا غاب إعداد أدوات SDK، يولّده هذا التحديث داخل SDK الأصلي. `flutter --version` لا يمر بهذا المسار. إذًا تجميد الغياب قبل أول أمر تطبيق وضع المرجع قبل اكتمال التهيئة.

أُعيد إنتاج الخلل على نسخة Linux مستقلة كاملة من SDK المثبت، مع حذف ملفات .dart_tool المولدة من النسخة التجريبية فقط وذاكرة حزم فارغة. استخدمت جميع الأوامر SDK نفسه وPATH وFLUTTER_ROOT وPUB_CACHE نفسها. نجح pub_get برمز صفر و351 بايت، وأنشأ في SDK `package_config.json` و`package_graph.json` و`version`، ثم رفض الحارس القديم التغير. بقيت جميع ملفات المصدر وملف القفل مطابقين. احتوى إعداد الحزم المحلي الجديد 102 حزمة وحقول configVersion وflutterRoot وflutterVersion وgenerator وgeneratorVersion وpackages وpubCache؛ تختلف المسارات والبصمات بين المضيفين ولا تُطبع قيمها.

الإصلاح يضيف مرحلة `provider_dependencies` صريحة قبل أخذ مرجع الملفات المولدة. تستخدم Dart الأصلي و`pub get --enforce-lockfile --no-precompile` داخل flutter_tools الأصلي، في بيئة الطفل نفسها التي ستستخدمها أوامر التطبيق. تُراجع ملفات المصدر والقفل قبل هذه المرحلة وبعدها، ويُتحقق من جذر إعداد الحزم المولّد. بعد نجاح التهيئة تُثبّت البصمات والبايتات لإعداد SDK وpackage_graph وversion، ثم تُجهّز نسخة التحليل المعزولة. لا إعادة أخذ مرجع لاحقًا، ولا استثناء لتغير pubCache أو generator أو metadata، ولا قبول لتغيرات عشوائية. أي تغيير لاحق أو ملف محذوف أو رابط رمزي يرفض التنفيذ.

تعلن أحداث SDK الآن تهيئة ملفات الاعتماديات المولدة صراحة، مع بصمة إعداد SDK قبل التهيئة وبعدها. عبارة عدم تعديل SDK تخص ملفات المصدر المثبتة؛ تهيئة .dart_tool مقصودة ومقيدة قبل تجميد المرجع. عند رفض ملف مولّد، ينشر `SDK_GENERATED_FILE_CHECK` دور الملف وحالته وحجمه وSHA-256 المتوقع والفعلي فقط، دون أسماء مسارات أو محتويات JSON أو قيم البيئة.

يفصل سجل GitHub بين `command_outcome` و`verification_phase` و`process_failure_kind`. عند نجاح الأمر وفشل فحصه اللاحق تظهر command_outcome=PASS وexit_code=0 وprocess_failure_kind=NONE، لكن النتيجة الكلية FAILED وfailure_kind=POST_VERIFICATION، مع السبب المحدد. فشل التحقق السابق يعلن NOT_RUN وPRE_VERIFICATION ولا يبدأ الأمر. لا ينتقل السائق إلى التحليل أو البناء عند أي فشل من هذه الحالات.

التجربة المصححة تستخدم SDK كاملًا واحدًا لكل الأوامر، وتثبت تطابق ملفات SDK المولدة بايتًا وبصمة قبل pub_get وبعده، وبعد التحليل واختبار الواجهة. تظل تجربة Linux وليست قبولًا لتنفيذ Mac؛ نجاح اختبارات انتظار Dart على Mac مثبت في المحاولة السابقة، أما اكتمال المسار الجديد على Mac فيتطلب التشغيل التالي من المشغل.
