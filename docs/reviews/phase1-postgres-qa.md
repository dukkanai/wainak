## ما ثبت

- بقاء الحساب والموافقات وإجابة الاحتياج والجلسة والعلاقة والبلاغ الوصفي
  بعد إعادة بناء الخدمة وإعادة تشغيل **حاوية قاعدة الاختبار**.
- rollback كامل عند فشل constraint أثناء حفظ الانتقال؛ لا أثر جزئي.
- تنافس عمليتين مستقلتين على الحصرية: فائز واحد، وعلاقة أخرى مجمدة.
- تنافس اتصالين على الحظر والتفعيل: الحظر هو الحالة النهائية دون صلاحية بطاقات.
- طلبات متزامنة بمفتاح تكرار واحد: علاقة دائمة واحدة.
- إعادة الطلب بعد الحظر تعيد الحالة الحالية، لا صلاحية قديمة.
- قيود DB تمنع الزوج المتكرر وclaim حصري مكرر، وتتطلب claimين صحيحين للحصرية.
- SQL metacharacters بقيت بيانات ولم تصبح تعليمة SQL.
- حذف الحساب الاصطناعي يبطل الجلسة ويزيل بياناته الخاصة والموافقات ذات الصلة؛
  يبقى للطرف الآخر سجل علاقة منتهية دون ملفه.
- لا token جلسة خام في مخزن الجلسات، ولا أعمدة محادثة/صورة/صوت/أدلة في المخطط.
  فحص الأعمدة ليس بديلًا عن مراجعة كل مسار بيانات إنتاجي مستقبلًا.
- initialization يرفض قاعدة خارج namespace التجريبي وقاعدة تحتوي schema سابقة.
- عبر JSON adapter: الطرف الثالث ممنوع من عمليات العلاقة وإسناد البلاغ، وpeer
  projection لا يتضمن حقولًا خاصة، ورفع المحتوى غير المنفذ مغلق، وبلاغ الشخص
  الذي حظره الهدف أولًا يبقى متاحًا. عيب QA-P1-001 السابق لم يعد موجودًا.

## عزل الاختبار وتنظيفه

راجعت مصدر harness قبل التشغيل. ينشئ اسم حاوية وvolume وقاعدة جديدًا، ويتحقق
من عدم وجودها، ويقيد الحاوية بـ `network=none` دون منافذ منشورة،
192 MiB و0.5 CPU. الاتصال عبر socket محلي داخل مجلد مؤقت خاص؛ السر الاصطناعي
ملف 600 داخل parent 700، ولا يدخل أمر الاتصال أو نتيجة الفحص.

التنظيف يتحقق من label/tag المملوكين للتجربة قبل إزالة الحاوية والvolume.
أخطاء Docker ليست دليلًا على غياب مورد. أثبتت نهاية التشغيل إزالة الحاوية
والvolume ومجلد السر/socket، ثم فحصنا مستقلًا قوائم Docker والمجلدات المؤقتة:
**صفر مورد اختبار متبقٍ**. حاوية المشروع الأصلية بقيت healthy في فحص metadata،
ولم نتصل بقاعدة بياناتها أو ننفذ عليها أي مهاجرة.

## حدود مهمة

- adapter correctness-first يحمّل ويستبدل حالة التطوير كاملة داخل معاملة مع
  advisory lock عام. هذا ليس إثبات سعة أو تصميم استعلامات إنتاجي.
- حساب قاعدة الاختبار إداري؛ لم نختبر دور تطبيق إنتاجي أقل صلاحية أو RLS.
- لا مهلة جلسات/مصادقة إنتاج، بريد فعلي، دفع، تشفير محادثة أو مراجعة أدلة.
- لا اختبار نقل خادم/نسخ خارجية/ضغط/توفر عالٍ أو تقييم اختراق شامل.
- اختبار JSON adapter هنا داخل العملية. سلسلة Flutter→HTTP→PostgreSQL مع إعادة
  تشغيل **خادم التطبيق** مرحلة قبول منفصلة قيد العمل؛ لا نستبدلها بنجاح هذا التقرير.
- فحوص الرفع المغلق لا تعني تنفيذ D25؛ الحذف هنا ليس سياسة احتفاظ إنتاجية
  أو إلغاء اشتراك أو محو نسخة لدى الشريك.

لا P0/P1 جديد مفتوح ضمن هذا النطاق. أي تغيير لاحق يحتاج إعادة الفحوص الملائمة.
لا يجيز التقرير دمجًا أو نشرًا أو التعامل مع بيانات حقيقية.
